# src/main/services

**职责**：中小型业务服务，一件事一个文件。

## 与 `features/` 的分界

同一个业务，**体量**决定放哪：

| 体量 | 放哪 |
|---|---|
| 一个文件装得下 | `services/<name>.ts` |
| 需要几个私有辅助文件 | `services/<name>/`（原地长子目录，不跳级） |
| 长成多文件的大领域、有自己的页面 | `features/<name>/` |

## 内容举例（将来可能出现的）

- 文件处理流水线
- 搜索与索引
- 知识库检索
- 导入 / 导出
- 备份

现在都还没有，此目录保持空。

## 铁律

1. **对外入口唯一**：`services/<name>/` 子目录只暴露一个 `index.ts`，其余文件私有。
2. **服务之间可以互相调用，但不能成环**。
3. **不做版本判断**：个人版 / 企业版差异归 `policy`。
4. **不直接碰 Electron**：需要平台能力时走 `core` 的接口注入。

## 依赖

允许依赖 `core`、`data`、`ai`；被 `src/main` / `ipc` 调用。

## 现状

已有 `chatReply.ts`（假流式回复，接真模型时替换的就是它）与 `assistantService.ts`（助手增删改查：校验 → 构造 → 落盘，依赖注入仓储与时钟，因此可脱离 Electron 单测）。
