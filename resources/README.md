# resources · 参考资料

收录**不属于项目本身代码/文档**的参考材料：论文、规范、手册、界面截图、竞品观察、随手摘录。

## 与其它目录的区别

| 目录 | 放什么 | 是否入库 |
| --- | --- | --- |
| `resources/` | 参考资料：PDF、截图、摘录、素材 | 是（受体积规则约束） |
| `ref/` | 外部项目源码（如 cherry-studio） | **否**，已在 `.gitignore` |
| `docs/` | 项目自己的规范与决策 | 是 |
| `resources/inbox/` | 临时丢进来的、还没整理的 | 否，已在 `.gitignore` |

判断标准：**它描述的是我们的项目，还是我们在参考的外部东西？** 后者放这儿。

## 目录

```
resources/
  papers/       论文、标准、协议文档（PDF/HTML 导出）
  guides/       官方手册、教程、最佳实践
  screenshots/  界面参考、竞品截图、设计样例
  notes/        阅读摘录、观察记录、对比结论
  inbox/        暂存区，未整理，不入库
```

## 收录规则

1. **单文件 ≤ 10 MB**。超了就别直接提交：传外部存储，在 `notes/` 里登记链接、来源、用途。
2. **注明出处**。每份材料在 `notes/` 或同目录 `INDEX.md` 留一行：来源链接、获取日期、为什么留它。
3. **不存版权敏感内容的大段复制**。摘要与引用可以，整本扫描件不行。
4. **不存密钥、账号、真实用户数据**，即使「只是参考」也不行。
5. 文件名用 `日期-来源-主题`，例如 `2026-11-cherry-studio-插件架构.pdf`，别用 `新建文档(3).pdf`。

## 清理

`resources/` 是仓库体积的主要膨胀源。每季度扫一次：三个月没被引用过的，删或移到外部存储。
