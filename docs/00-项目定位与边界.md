# 00 · 项目定位与边界

## 一句话

PointStudio 是一个 **AI 工作台**：用户把任务丢进来，工作台负责理解、规划、调用能力、产出结果，并留下可追溯的过程。

## 两个版本

| | 个人版 | 企业版 |
| --- | --- | --- |
| 使用者 | 单人有开发者/创作者 | 组织内多人、有管理员 |
| 部署 | 本地 / 单机优先 | 私有化部署，可离线、可集群 |
| 账号 | 单账号，可无账号 | 组织 + 角色 + 权限（RBAC） |
| 数据 | 本地存储，用户自持 | 数据不出域，分级存储与保留策略 |
| 模型 | 用户自带 API Key 为主 | 统一网关、配额、成本核算 |
| 审计 | 轻量日志 | 全量可审计：谁、何时、对什么做了什么 |
| 计费 | 无 | 席位数 / 用量 / 混合 |
| 扩展 | 用户自装插件 | 管理员分发、白名单、版本锁定 |

**共同内核**：任务理解与规划、能力（工具）调用、上下文管理、会话与产物管理。两版共享内核，差异通过**能力开关 + 策略层**表达，而不是 fork 两份代码。

## 边界：现阶段明确不做

- 不做通用云 IDE、不做代码托管（复用 Git）。
- 不做模型训练/微调平台（只做接入与路由）。
- 不做即时通讯、不做文档协同编辑。
- 个人版不内置多租户；企业版不承诺 SaaS 公网托管形态。

## 分层原则（用于判断代码该放哪）

```
src/main/     主进程：窗口、生命周期、组装
src/renderer/ 渲染进程
  src/main/     主进程入口 + 内核目录（core/ipc/data/ai/...）
ref/       外部参考代码，只读，永不提交
docs/      规范与决策
```

判断标准只有一条：**换掉外壳时，它还需要存在吗？** 需要 → `src/main/` 下的内核目录。

## 许可

- **客户端（`src/` 全部）：Apache-2.0。** 允许商业闭源使用，自带明示专利授权与专利报复条款。
- **企业版服务端（`src/server`）：闭源，仅作为云服务运营、不对外分发**，因此不触发许可证的源码附随义务。
- ⚠️ 若将来改为**私有化交付**（把服务端装进客户的机器），分发即触发 Apache-2.0 的附随义务（需随附许可证与修改声明）。届时要重新评估，不能默认沿用本条。
