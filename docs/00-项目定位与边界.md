# 项目定位与边界

PointStudio 是一套面向小说与游戏内容创作者的 **本地优先（Local-First）双屏多智能体工作台**。它吸收了 Cherry Studio 的丰富配置与权限档位、Orca 的驻场数字员工（`SOUL` + `MEMORY` + 交接闭环）、T3 的极速响应与旁路快问（`/side`）、以及 Paseo 的透明并行子泳道与回执审计，将**「纯粹对话」「单智能体养成」「智能体小组路由协同」**与**「双屏创作画布」**融为一体。

---

## 1. 竞品对标与差异化锚点

| 维度 | Cherry Studio | Orca | T3 | Paseo (Pesao) | **PointStudio（我们的目标）** |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **核心隐喻** | 全能模型/知识库工具箱 | 驻场 Bot 团队与工单群聊 | 极速纯净的开发者聊天流 | 并行编码执行器与透明泳道 | **双屏创作画布 × 可养成的驻场专家与无组长敏捷小组** |

| **模型与运行时** | 云端 API + 本地 Ollama | CLI Coding Agent 编排 | 云端 API 流式 | 本地 CLI Agent 进程 | **直连 API + CLI 智能体引擎（OpenCode/Paseo/Devin/Command）+ 本地模型三轨统一** |

## 2. 三大交互模态的核心功能目标

PointStudio 严格区分三种使用心智，拒绝把所有对话都塞进同一种臃肿界面：

### 2.1 普通对话模式（Chat Mode —— T3 级纯粹与极速）
- **零摩擦开聊**：不强制绑定智能体，打开即聊，直接引用当前 `Project` 工作区内的设定文档与章节切片。
- **`/side` 旁路临时快问（Ephemeral Side-Chat）**：在阅读或写作中途需要查一个典故、算一组数值或试写一段描写时，可在右屏唤起 `/side` 临时问答；**旁路问答默认用完即焚、绝不污染左屏主会话上下文**，仅在点击「采纳并插入」时才写入主对话或右侧文档。
- **双轨模型对比（Dual-Track）**：支持同一问题并行拉起两个模型（或两条策略）同屏盲测对比，一键采纳胜出版本。

### 2.2 单智能体模式（Single Agent Mode —— Orca + Cherry 级「驻场专家养成」）
- **极简出生证明**：每个驻场智能体由 **3D 语义头像** + **名称** + **`≤200` 字 `Soul`（核心职责与边界，非长篇指令杂烩）** + **三档权限模式（`auto-edit` 自动接受编辑 / `smart` 智能批准 / `full-access` 完全访问）** + **绑定模型或 CLI 引擎（缺省跟随 `🐼 Auto · 协同路由`）** 构成。
- **私域记忆沉淀（`Memory Spark`）**：驻场专家不止是一段静态 `systemPrompt`，它拥有独立的私域记忆作用域（`Agent Memory`）与共享的项目记忆（`Project Memory`）。对话中浮现的关键设定或避坑规则，可一键沉淀入该专家的记忆库，越用越懂项目。
- **五态呼吸灯与子泳道**：左侧栏实时映射专家的五种真实生命周期（`working` 绿呼吸 / `waiting` 黄常亮待人类确认 / `error` 红常亮 / `idle` 灰绿在线 / `disabled` 空心停用），执行工具时自动展开紧凑的后台子泳道（Sub-lanes）。

### 2.3 智能体小组模式（Agent Squad Mode —— Orca + Paseo 级「路由拆解与双屏车间」）
- **拖拽建组与跨组兼任**：通过拖拽头像即可创建小组，同一位专家（如「世界观考据」「数值策划」「文风润色」）可同时归属多个小组（`mode: 'multi'`），无需重复克隆配置。
- **去固定组长化 —— 基于 `Soul` + `PandaRouter` 的动态任务拆解**：
  - 小组**不设死板的固定组长（No Fixed Lead）**；
  - 当用户向小组下达复合需求时，系统结合组内各成员的 `Soul` 职责签名与本地 `PandaRouter` 协同路由，自动将目标拆解为子任务卡（Task Cards）并精准派发给对应成员并行执行。
- **左屏胶囊降噪 + 右屏 Paseo 车间**：
  - **左屏主群聊拒绝刷屏**：成员之间的派单与移交只渲染为单行**交接胶囊（`HandoffPill`）**，顶部提供**任务漏斗条（`Mission Bar`）**支持按特定成员或交接链路过滤；
  - **微回执卡片（`Micro-Receipt`）与诚实标记（`Honesty Flags`）**：成员交活时产出结构化微回执（结论摘要 + 产物跳转锚点 + 主进程校验的真实文件变更/命令退出码标记，杜绝大模型「嘴上说改完其实没动」）；
  - **右屏分屏画布（`SecondaryPane`）**：承载 `会话 / 页面 / Markdown 产物 / 交接轨迹 (Mission Trace)`，点击左屏任一胶囊或成员头像，右屏立即切入该成员的实时推理车间或产物对比。

## 3. 全局设置 6 大分级与「API + CLI 双轨模型 + 四层浏览器」架构蓝图

设置中心采用 **左栏 6 大一级分组 + 二级菜单导航**，将 AI 核心能力置于第一级：

| 一级分组 | 二级模块清单 | 核心架构设计 |
| :--- | :--- | :--- |
| **1. AI Agent** | ① **默认模型** · ② **模型服务** · ③ **本地模型** · ④ **路由编排** · ⑤ **MCP 服务** · ⑥ **Skills 技能** · ⑦ **记忆与知识库** · ⑧ **用量与审计** | - **模型服务双轨制**：<br>  1) **直连 API (`kind: 'api'`)**：DeepSeek、OpenAI 兼容接口（SiliconFlow / OpenRouter / Kimi / Qwen 等）、Anthropic、Gemini，由主进程 HTTP/SSE 流式驱动；<br>  2) **CLI 智能体引擎 (`kind: 'cli'`)**：一等公民接入本机 **OpenCode (`opencode`)**、**Paseo (`paseo`)**、**Devin (`devin`)**、**Claude Code (`claude`)**、**Codex (`codex`)** 及 **自定义命令 (`custom-command`)**，支持可执行文件探活、参数模板与**三档权限模式（`auto-edit` / `smart` / `full-access`）的命令行参数自动桥接**。<br>- **默认模型四槽位**：主对话模型、轻量快反模型（标题/`/side`/记忆提炼）、规划与小组拆单模型、知识库向量模型。<br>- **本地模型**：Ollama / LM Studio 免 Key 端口探活与上下文预算。<br>- **用量与审计**：同时统计 API 模型的 Token 账本与 CLI 引擎的调用次数、耗时及退出码成功率。 |
| **2. 基本设置** | ① **通用设置** · ② **快捷键** · ③ **代理** · ④ **关于 PointStudio** | 语言、启动恢复、工作区默认路径、全局快捷键、供 API/CLI/MCP 复用的 HTTP/SOCKS5 代理、版本与开源许可。 |
| **3. 工作流程** | ① **Git 和源代码控制** · ② **自动化** · ③ **终端** · ④ **浏览器** | - **Git 与快照**：代码与创作文稿的版本快照点。<br>- **自动化**：定时与事件触发器。<br>- **终端**：默认 Shell（PowerShell / Git Bash / WSL）与沙箱工作目录策略。<br>- **浏览器（四层 Agent 浏览器架构）**：不做给人类刷网页的笨重传统浏览器，而是构建 **① 免浏览器极速提取/API 优先 → ② CDP 无障碍树 (`AXTree @eN`) + `Set-of-Mark (SoM)` 视觉数字便利贴双模感知 → ③ 右屏 `SecondaryPane` 实时副驾画面与遇登录/验证码/`smart` 高危拦截时的一键人类接管 → ④ 一次探路自动固化为本地 Skill**。 |
| **4. 界面** | ① **外观与颜色** · ② **字体与字号** · ③ **通知** | 深浅色单色（Monochrome）主题切换、界面缩放、UI 字体与代码等宽字体（`Geist Mono`）、字号行距、后台长任务完成或待审批提醒。 |
| **5. 实验性** | ① **插件** · ② **前沿特性开关** | 运行时插槽（`Slots`）扩展插件管理、实验性 Feature Flags。 |
| **6. 隐私和安全** | ① **全局权限护栏** · ② **凭据管理** · ③ **数据与备份** | 全工作区最高权限上限锁（如全局锁死最高 `smart` 禁止 `full-access`）与高危命令黑名单、API Key 脱敏审计与一键吊销、全库备份导出/合并导入/整体恢复。 |

## 4. 明确不做的事（边界护栏）

1. **不做云端账号强绑定与强制遥测**：所有会话、智能体、小组、记忆、用量账本与知识库切片 100% 存储在本地可控目录，断网状态下仍可使用本地模型与全部文稿管理能力。
2. **不做给人类冲浪用的传统内嵌浏览器标签页**：拒绝在主窗口内塞入带书签栏、历史记录的通用 Web 冲浪浏览器；浏览器能力严格限定为 **Agent 受控自动化手脚（CDP / `agent-browser`）+ 右屏实时副驾接管与产物预览画布**。
3. **不做花哨装饰型 UI**：坚持高对比度单色（Monochrome）工作台美学，色彩仅用于传递语义状态（五态状态灯、权限风险等级、Diff 增删），绝不引入营销插画或无意义渐变。

## 5. 演进纪律：先立功能骨架，后做集中 UI 精修

针对探索期「边做边想、功能快速演进」的特点，研发推进严格遵循三步节奏，避免在功能未定型时陷入局部像素返工：

1. **第一步：契约与纯函数先行（Contract & Pure Lib First）**
   - 任何新功能先在 `src/shared/types/ipc.ts` 落定纯 JSON DTO 契约，并在 `src/renderer/src/lib/*.ts` 或 `src/main/ai/domain/*.ts` 编写零 UI 依赖的纯函数与单元测试。
   - 这一步成本最低、改动最快，用于快速验证业务规则。
2. **第二步：功能骨架跑通真数据（Functional Skeleton with Real Data）**
   - 界面层先复用现有 `tokens.css` 语义变量搭出干净可用的交互骨架，**核心考核指标是「100% 真实数据闭环、零假按钮、主进程校验兜底」**；
   - 在功能探索期，不死抠非阻塞的局部像素微调。
3. **第三步：里程碑封板后集中 UI 走查（Batch UI Polish on Milestone）**
   - 当一个完整功能模块骨架全部跑顺并定型后，再启动真窗口截图走查，一次性完成字重、间距、浮层层级与视觉细节的统一收口。
