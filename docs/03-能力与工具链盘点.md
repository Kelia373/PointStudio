# 03 · 能力与工具链盘点（当前执行 agent）

记录本机这套 agent 实际能干什么、边界在哪，供后续任务规划时判断「这件事能不能做、要几步」。

> 环境：Windows 主机，工作区 `D:\Project\PointStudio`，DSH（DeepSeek Harness）Web GUI `http://127.0.0.1:1661`。
> 本文件只描述**已验证**的能力；标注「未验证」的不要当成可用。

## 1. 执行与文件

| 能力 | 用途 | 约束 |
| --- | --- | --- |
| shell（bash/MSYS） | 命令、git、构建、临时脚本 | 默认沙箱 `workspace-write`；**HTTPS 出网被阻断** |
| 文件读写/编辑 | 精确改代码 | 单文件、UTF-8 |

## 2. 网络与外部世界

- 网页搜索 / 抓取、页面精读（含 JS 渲染页面）。
- 浏览器自动化：**用户真实 Chrome**（带登录态，可建仓、填表、下载）+ agent 独立浏览器实例。
- 访问 GitHub API / git 推送：**必须申请 `danger-full-access`**，否则 HTTPS 直接失败（`curl` 返回 35）。
- 已知 Git 环境：`git 2.56`，无 `gh` CLI、无 SSH key、无 credential manager；凭据走 `~/.git-credentials`（`credential.helper=store`）。

## 6. 环境坑（已验证，会反复遇到）

1. **HTTPS 出网**：`workspace-write` 下任何 HTTPS 请求失败；涉及 GitHub、包下载、API 时必须提权。
2. **Windows 保留名**：文件名 `CON`/`NUL`/`AUX` 等会让 `git add -A` 失败且读取挂起；删除需 `[System.IO.File]::Delete('\\?\路径')`。
3. **`.gitconfig` 初始不存在**：首次 `git config --global` 前任何读取全局配置的命令都会报错，属正常。
4. **GitHub 表单**：受控 React 输入，模拟键入会丢失，需走原生 setter + 事件派发；按钮在视口外时坐标点击无效。
5. **工作区目录会阻止 exe 执行（本项目最大的坑）**。DSH 给每个 session workspace 目录加 ACL 加固，**工作区内的 exe 在用户的普通 PowerShell 里静默失败**——无 stdout/stderr、退出码 0、不执行 JS、Windows 事件日志无记录、程序自己的日志文件也不生成。
   实测证据（同一 electron.exe、同一机器、唯一变量是位置）：

   | 位置 | `--version` | 执行 JS |
   | --- | --- | --- |
   | `C:\Users\Administrator\etest`（工作区外） | 打印 `v45.4.1` | 正常 |
   | `D:\etest`、`D:\Project\etest2`（工作区外） | 正常 | 正常 |
   | `D:\Project\PointStudio\...\electron.exe`（工作区内） | **无输出** | **不执行** |

   `NewGame` / `PointStudio` / `PointStudio-Enterprise` 三个工作区都带同样加固（`Everyone:(CI)(DENY)(DC)`、`S-1-4-<SID>:(OI)(CI)(W,D,DC)`、显式 `Administrator:(WO,S)`），非工作区目录没有。
   **判断方法**：`icacls <目录>` 看有没有 `S-1-4-` 与 `Everyone:(CI)(DENY)`。
   **注意**：Low 完整性级别**不是**障碍——AI 复制出的文件（Low IL）用户也能执行。唯一障碍是工作区目录本身。
   **解法**：依赖装在工作区外（`D:\deveTools\ps-node`），用 `New-Item -ItemType Junction` 把 `node_modules` 与 `apps/*/node_modules` 链进工作区。**改 `package.json` 依赖后必须同步到 `ps-node` 再 install。**
   **"换目录重建 workspace"无效**——新工作区会被同样加固。
6. **pnpm 11 的配置位置**：`storeDir` 与 `allowBuilds` 只能写在 `pnpm-workspace.yaml`；`.npmrc` 里的 `store-dir` 不生效；`package.json` 的 `pnpm` 字段 v11 已不再读取（旧写法 `onlyBuiltDependencies` 已被 `allowBuilds` 映射取代）。验证：`pnpm store path`。
7. **electron 二进制可能装不上**：pnpm 会跳过 postinstall，装完没有 `dist/`。需在 electron 包目录执行 `node install.js`，且必须带 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`（本机直连 GitHub HTTPS 被阻断）。次要问题：`%APPDATA%\Roaming\Electron` 若被沙箱进程创建过，可能报 `Unable to create cache`，删掉该目录让它重建。
8. **DSH 会话给子进程注入 `ELECTRON_RUN_AS_NODE=1`**：electron 被当纯 Node 跑，报 `Cannot read properties of undefined (reading 'whenReady')`。跑 electron 前必须 `unset`。
9. **GUI 程序的 stdout 在 Windows 会丢**：判断"是否真的执行了"必须让程序自己写文件；`cmd /c "... 2>&1"` 拿不到输出，要用 `Start-Process -RedirectStandardError`。**AI 在会话内也无法启动 Electron 窗口**（`0xC0000005`），窗口只能由人开终端确认。
10. **PowerShell 执行策略拦 `.ps1`**：`.\node_modules\.bin\xxx` 报「未对文件进行数字签名」。绕法：显式 `.CMD` 后缀或用 `bash`。长期方案 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`——改系统设置必须人做。
11. **TypeScript 7 移除了 `baseUrl`**：`paths` 必须写相对路径 `./src/...`（报 TS5102 / TS5090）。
12. **Vite 热更新需要轮询**：本仓库目录下 Vite 的文件监听不触发，需在 `renderer.server.watch` 设 `usePolling: true`。**主进程（`src/main`、`src/preload`）改动不会自动重启**（Vite 8 用 Rolldown，无轮询开关），必须手动重启 dev。判断 HMR 是否工作看 **app 窗口的 DevTools 控制台**（`[vite] hot updated`），不是终端；该日志属 verbose 级，默认折叠。
13. **GitHub 细粒度 PAT 权限**：创建仓库、改默认分支、配分支保护都需要相应 scope；缺权限时返回 `403 Resource not accessible by personal access token`。推送 `.github/workflows/` 需要 `Workflows: Read and write`。

## 7. 能力缺口（做规划时必须考虑）

- 无 CI/CD 配置、无测试运行环境（技术栈未定）。
- 参考代码已在本机：`D:\Project\NewGame\ai-workstation\ref\cherry-studio`（**不在本仓库内**，不属于本仓库，只读）。
  注意它是以 `--filter=blob:none --no-checkout` 浅克隆的，工作区只有 `.git`。
  要读源码先在那边执行 `git sparse-checkout set src docs packages scripts && git checkout -f HEAD`；
  不读源码时可以直接用 `git show HEAD:<path>` 取单个文件。
- 无生产级密钥管理方案，企业版相关设计需单独定。
