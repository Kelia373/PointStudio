# 渲染进程结构（`src/renderer`）

渲染层的目录约定、组件组织方式，以及「界面不碰数据」这条硬规则。


## 现状

工作台外壳已按单色设计基线重做（参考 `D:/Project/PointStudio-ui/prototype/index.html` 的实现，**没有把原型文件搬进仓库**）：

- `styles/tokens.css` —— 颜色 / 圆角 / 间距 / 四档动效时长的唯一来源；组件样式只许引用变量，不写裸色值与裸毫秒。
- `styles/app.css` —— 组件样式，按「外壳 / 侧栏 / 主区 / 消息流 / 输入区 / 检查器 / 抽屉」分段。
- `components/ChatPanel.tsx` —— 状态与订阅仍集中在这里（`useState`，没引状态管理）。
- `components/Sidebar.tsx` —— 会话列表 + 功能区，可收成 64px 图标轨。
- `components/Composer.tsx` —— 输入区三态（发送 / 生成中 / 停止）、高度自适应、Enter 发送。
- `components/EmptyState.tsx` —— 空状态四张建议卡，点击只填入输入框、不直接发送。
- `components/Inspector.tsx` —— 右检查器三视图：上下文 / 工具调用 / 运行。
- `components/MessageBubble.tsx` —— 纯展示，只有 props；悬停出操作（复制 / 重发 / 删除整轮）。
- `components/Annotate.tsx` —— 标注模式：点界面元素选标签写备注，底部条汇总、一键复制。纯前端，标注存 `localStorage`。
- `lib/clipboard.ts` —— 复制统一入口：优先走主进程 `clipboard:write-text`，失败再退浏览器 API（浏览器 API 在部分环境**永不 resolve**，必须带超时）。

仍然没有组件库、没有路由、没有状态管理方案。界面类改动的最终效果必须人在真窗口确认。

### 标注模式怎么开 / 怎么彻底关掉

顶栏的 **✎** 就是开关。要移除这个功能，注释掉 **一行**即可：

- `src/renderer/src/components/ChatPanel.tsx` 顶栏里标了 `ANNOTATE` 注释的那个 `<button>`（搜索 `ANNOTATE` 能直接定位）。
- 与该按钮同生共死的 `<Annotate … />` 在文件末尾，同样带 `ANNOTATE` 标记；按钮注释掉后它不会被挂载，一并注释更干净。

为什么这么设计：标注是**给我和你对齐用的评审工具**，不是产品功能，所以它必须能一行去掉，且不牵动业务代码。

## 唯一一条硬规则

**渲染进程不直接碰文件、数据库、模型 API。全部经 IPC 走主进程。**

理由不只是安全：渲染进程本来就是浏览器环境，没有 Node 能力；一旦为了省事打开 `nodeIntegration`，界面和业务会迅速糊在一起，之后想拆就拆不开。

## 目录约定（需要时才建）

```
src/renderer/
├── index.html
└── src/
    ├── main.tsx          React 入口
    ├── App.tsx           根组件
    ├── pages/            页面，一个页面一个文件或目录
    ├── components/       可复用组件
    ├── hooks/            自定义 hook
    └── styles/           全局样式
```

**默认不要建任何目录。** 第一个页面出现时建 `pages/`，第一个复用组件出现时建 `components/`。空目录不提供任何价值，只会诱使人往里塞东西。

### 组件：单文件还是目录

- 单文件组件保持扁平：`components/MessageBubble.tsx`
- 只有它带上私有子组件 / hook / 样式时才建目录：

```
components/MessageBubble/
├── index.ts            再导出（.ts 不是 .tsx —— 它没有 JSX）
├── MessageBubble.tsx   主实现（不要叫 index.tsx）
└── useBubbleSize.ts    私有 hook
```

### 页面之间不许互相 import

`pages/A` import `pages/B` 是跨页耦合——改 B 会炸 A。共用部分下沉到 `components/` 或 `hooks/`，让两个页面各自去 import。

## 反模式

- 在组件里直接调模型 API —— 走主进程
- 在组件里读写文件 —— 同上
- 页面 import 另一个页面
- 为一个组件预建目录
- 把业务逻辑写进组件（那属于 `src/main/ai/`）

## UI 与功能的落差清单

按「能不能接上」分三类。**A 类已经在这轮接上；B 类缺数据，不伪造，界面显式写「未统计 / 未接入」；C 类功能有但界面没适配好。**

### A. 已接上（本轮）

| 界面能力 | 数据来源 |
| --- | --- |
| 三栏布局 + 侧栏 260↔64 图标轨 + 检查器开关 | 纯界面状态 |
| 深 / 浅主题 | `localStorage`，`html[data-theme]` |
| 消息复制 / 重发 / 删除整轮 | 现有 IPC（`conversations.deleteTurn` 等） |
| 引用点击看原文片段 | `workspace.readChunk` |
| 输入区三态、停止生成 | `chat.send` / `chat.cancel` |
| 顶栏模式 chip（真模型 / 本地假流式 / 未发送） | `chat.send` 返回的 `mode` |
| 上轮生成耗时 | 渲染层自己计时（真实值） |
| 检查器「上下文」：会话、助手、模式、消息数、引用数、平台、模型、采样参数 | `conversations.list` + `settings.readProvider` |
| 检查器「工具调用」：Agent 步骤的工具与耗时、已连接 MCP 服务 | `agent.onEvent` 的 `details` + `mcp.list` |
| 检查器「运行」：Agent 进度与每步状态 | `agent.onEvent` |
| 设置 / 助手 / 工作区 / 计划 → 右侧抽屉 | 现有面板组件原样挂入 |

### B. 原型有、我们没有数据（未适配）

| 原型元素 | 拦在哪 |
| --- | --- |
| Token 计数（单轮 / 上下文占用 / 上限） | provider 的 `usage` 没被解析与落库；界面显示「未统计」 |
| 首字延迟（TTFT） | 流式事件没带时间戳，只有总耗时 |
| 结束原因（完成 / 停止 / 超长 / 报错细分） | 消息只有 `status`，没有细分 reason；要加可选字段（按消息 schema 演进规则） |
| 顶栏切换模型（Zen-4 / mini） | 我们只有全局 provider 设置，**没有「会话级模型」概念**——这是产品决策，不是补字段 |
| 消息「有帮助」反馈 | 无后端，本轮未做 |
| 单轮工具调用可视化（普通对话里调了哪个工具、参数、结果） | 内置工具还没接进对话执行链；只有 Agent 步骤级信息 |
| ⌘K 命令面板 | 需要命令注册表，本轮未做 |
| 素材库 / 网格密度视图 | 没有素材库能力，属未来模块 |
| 标注模式（点元素打标 + 复制标注） | 原型里的**评审工具**，有意不进产品 |

### C. 功能有、界面没适配好（需要重新设计的地方）

1. **计划面板入口丢了**：抽屉关掉后没有「最近计划」入口，只能再点一次「🧭 计划」重新生成。应在检查器「运行」或侧栏给一个常驻入口。
2. **助手选择是原生 `select`**：和单色体系不搭，也没有「当前助手」的提示。建议自绘 popover。
3. **设置仍是长表单**：输入框/按钮已统一到 token，但分组、分段控件、危险操作（清空 Key）的层级没重排。
4. **工作区面板只有文件列表**：没有「这些文件被引用了多少次 / 哪些进了上下文」的信息。
5. **多模型对比有服务无界面**：要并排还是一条结果切换？布局未定。
6. **会话改名没接界面**：通道已有，侧栏没有重命名入口。
7. **消息时间不显示**：`MessageDto` 没把时间暴露到界面（气泡上留了 `at` 位）。
8. **错误提示只在顶部 banner**：多条错误会互相覆盖，失败原因应贴到对应消息上。
9. **长会话没有「回到最新」/ 未读提示**。
10. **窄屏只做了 1080 以下强制折叠**，不是真正的响应式。

### D. 要人定的决策（影响后续设计）

1. 模型要不要做成**会话级**（顶栏 chip 切换）？还是保持全局设置？
2. 「本轮工具调用」要不要做成检查器的主视图（等内置工具接入执行链后）？
3. 多模型对比：并排分栏，还是结果切 tab？
4. Agent 步骤的**产物**在哪展示、产物指文件还是文本片段？
