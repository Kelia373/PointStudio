# 04 · 能力地图（模块归属 · 里程碑 · 状态）

本文回答一个问题：**「AI 工作台」这个品类的基本能力有哪些、每一项落在哪个模块、做到什么算完成。**

它不记录任务进度流水，只记录**现在成立的结论**：能力归属、验收判据、当前状态。状态变了就改这一页，不加新章节。

模块开发结果后，需要同步更新或者在references建立对应的说明文档。

## 1. 本文与其他文档的分工

## 2. 分层与模块归属

能力按**性质**分层，每层只落到固定目录——这是 `docs/references/architecture/main-architecture.md` 的封闭顶层治理决定的，不按「先写在哪个文件方便」决定。

| 层 | 归属目录 | 只装什么 |
| --- | --- | --- |
| ① 模型接入 | `src/main/ai/providers/` | 平台实现口与各平台实现，禁止业务规则 |
| ② 对话与上下文 | `src/main/ai/domain/` + `src/main/services/` | 消息/会话的模型与纯规则；流式编排归 services |
| ③ 助手与任务 | `src/main/ai/domain/`（模型）· `src/main/ai/agent/`（规划执行） | 助手是配置实体；任务是计划实体，两者不混 |
| ④ 知识与文件 | `src/main/services/` + `src/main/data/` | 文件登记归 services，检索索引归 data |
| ⑤ 工具扩展 | `src/main/ai/tools/` | 统一 `Tool` 接口与注册表，不做权限判断 |
| ⑥ 数据与工程化 | `src/main/data/` · `src/main/core/` | 仓储与适配器；路径/日志/窗口等运行时 |
| ⑦ 界面 | `src/renderer/` | 只显示与收集输入，不碰数据与模型 |
| 跨进程边界 | `src/main/ipc/` + `src/preload/` + `src/shared/types/` | 通道、白名单、共享类型 |
| 策略（仅企业版） | `src/main/policy/` | 权限、配额、审计；个人版不用 |

**依赖方向只许向下**：`界面 → ipc → services → ai/domain → data → utils`。`core` 不认识业务，`utils` 零依赖。

## 4. 里程碑与出口条件

| 里程碑 | 内容 | 出口判据 |
| --- | --- | --- |
| **M1** | 模型接入 + 会话消息落库 + 多会话 + 助手接进对话 + Key 设置界面 | 关窗重开，历史还在；选助手后回复风格真的变了 |
| **M1.5** | SQLite 适配器 | 同接口替换 JSON，测试不改一行 |
| **M2** | 任务对象 + 计划可视 + 自主 Agent + 上下文管理 + 中断 | 给一个多步任务，能看到计划、每步状态、失败原因 |
| **M2.5** | 工作区与文件拖入 | 拖一个文件进来，重启后仍可引用 |
| **M3** | 知识库 RAG + 工具/MCP + 第二个平台 | 回答能引用导入文档；外部工具可调用 |
| **M4** | 多模型对比 + 崩溃报告（本地）+ 导出备份 | 报告可导出且不含凭据与消息正文 |

## 5. 六条「能不能叫 AI 工作台」

1. 配 Key → 选模型 → 流式聊得起来
2. 关掉再开，会话还在
3. 会话能建能切能删，历史不撑爆上下文
4. 多步任务能看到计划和每步状态
5. 能导入文档，回答带引用
6. 除模型调用外，主体可离线使用

六条全绿才谈特色功能。特色只能加在层之上，不能拿来补层。

## 6. 怎么维护本文

- **能力变了**才动本文：新增能力、判据变化、状态翻绿。
- 状态翻绿必须**同时**满足：有契约测试 + 通过 `tsc` + 构建通过。
- 界面类能力翻绿额外要求**人工确认过窗口效果**（AI 无法启动 Electron 窗口）。
- 不在本文写「计划中」「进行到一半」这类过程信息——那属于 PR 与提交信息。
- **状态只写两处**：代码级「这个目录里有什么」写各目录 `README.md` 的 `## 现状`；能力级「能不能用」写本文 §3；没有目录 README 的地方（如 `src/renderer`）用 `docs/references/architecture/` 下对应文档。`src/main/ai/*.md` 这类模块契约文档**不写现状**——写了必然过时。
