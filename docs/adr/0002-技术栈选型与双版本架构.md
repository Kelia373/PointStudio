## 目录骨架

```
apps/desktop      个人版壳（Electron），只做组装
apps/server       企业版壳（占位），只做组装
packages/core     领域模型与用例：纯 TS、零 IO、零 UI
packages/agent    规划/执行循环
packages/providers 模型接入层
packages/tools    工具协议与注册表
packages/policy   策略层：权限/配额/审计/鉴权（两版差异唯一落点）
packages/storage  存储接口 + sqlite/postgres 适配
packages/remote   protocol + transport（企业版才用，接口先定）
packages/ui       共享组件（仅 desktop 依赖）
```

## 双版本并行的六条纪律

1. **内核不知道自己在哪个版本**。`core|agent|tools|providers` 中禁止 `if (isEnterprise)`、禁止 import electron、禁止直接读环境变量。
2. **差异只准出现在 `packages/policy` 与 `apps/*`**。散落到业务代码即视为架构违规。
3. **依赖注入边界**：storage / transport / clock / logger / auth 全部接口注入。
4. **存储与传输可替换**：SQLite ↔ Postgres、in-process ↔ HTTP/WS；协议定义先于实现。
5. **审计事件在核心里发**，落盘方式由 `apps` 决定——不要等做企业版才补埋点。
6. **不硬编码单用户假设**：`userId` / `tenantId` 从第一天就作为参数，个人版传 `local`。

## 备选与取舍

| 备选 | 结论 | 理由 |
| --- | --- | --- |
| Tauri | 否 | agent 依赖 Node 生态、子进程、native 模块；Rust 侧等于重写桥 |
| Next.js 服务端优先（LobeChat 式） | 否 | 个人版要求本地优先、离线可用 |
| 自写多 provider 适配 | 否 | AI SDK 已覆盖，自写是纯负债 |
| Nx / Turborepo | 否 | pnpm scripts 足够，早期引入只增加认知成本 |
| 引入向量库（LanceDB 等） | 暂缓 | RAG 不是当前阶段重点，按需再定 |
| AGPL 参考代码 | **禁止复用** | 传染性会波及闭源企业版 |

## 后果

**正面**：内核可单测、两版不分裂、模型接入零成本扩展、企业版可复用全部内核。

**负面**：前期必须在抽象层投入（policy / storage / transport 接口），短期看不到界面产出；Electron 安装包体积大。

## 风险

- **policy 层空壳化**：企业版未启动时容易写成摆设，导致真正需要时无处落差异 → 立即建接口，哪怕实现为空。
- **Electron 分发**：企业版内网部署与自动更新方案未定。
- **better-sqlite3**：native 模块，跨平台构建与升级 Electron 版本时需重新编译。
- **AI SDK 迭代快**：大版本升级需评估 breaking change，锁定次版本范围。
- **许可证合规**：Apache-2.0 需保留 `LICENSE` / `NOTICE` 与修改声明；参考代码只学思路。
