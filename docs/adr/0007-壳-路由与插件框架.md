## 一、背景与要解决的核心矛盾

PointStudio 需要同时满足四件事：

1. **高自由度插件整合（对标 DSH）**：允许插件作者按需往客户端加整页新功能（如「会话-Agent 网络调度拓扑图」「Panda 协同路由战力看板」）、在局部插槽塞微件、甚至**直接替换内置 UI 组件**（如消息气泡、输入栏），权限交由插件作者，安装即信任。
2. **故障绝不陪葬（崩溃自愈与回滚）**：不阉割插件权限，但插件写崩、死循环或抛异常时，不能让宿主白屏，必须保留用户一键禁用或自动回退的能力。
3. **PointStudio 独家交互辨识度（区别于 Orca / T3 Chat / Paseo）**：围绕「培养 Agent 特工队 + 派遣到项目 + 本地协同路由逆袭大模型」形成独有体验，而不是做成传统冷冰冰的 IDE 文件树。
4. **60fps 极致丝滑 + 面向将来新仓库 Rust 重写的零耦合边界**：当前在 TS/Electron 客户端解决流式高频重绘与同步 I/O 卡顿；同时严守跨进程纯 JSON 契约，保证将来切 Rust（Tauri / Rust Daemon）时 `src/renderer` 与所有 UI 插件**零改动无缝复用**。

## 二、核心架构决策

### 1. 废除「三表分离」，合拢为单一的 `Slot & View Registry`

不再拆成互相同步的路由表、导航表、组件表，统一由 `src/renderer/src/runtime/registry.ts` 管理三类挂载原语：

| 原语 | 方法 | 消费方式 | 用途 |
| --- | --- | --- | --- |
| **整页视图 (`Page`)** | `registerPage(def)` | 挂载到侧栏功能区（`sidebar.features`）并注册到中央舞台 `PageStage` | 新增独立功能页（调度拓扑、协同路由看板、任务看板、全屏设置） |
| **区域插槽 (`Slot`)** | `registerSlot(slotName, comp, order)` | `<Slot name="..." />` 按 `order` 顺序追加渲染多个组件 | 在既有界面坑位里塞按钮、状态灯、工具条 |
| **组件覆盖 (`Override`)** | `overrideComponent(key, comp)` | `<Overridable name="..." fallback={Builtin} />` 优先取最新覆盖，无覆盖或报错时渲染 `Builtin` | 替换内置核心零件（气泡、输入区、空状态、检查器、会话项） |

**硬规则：内置功能与插件地位平等。** 侧栏现有的 `FEATURES`（任务看板、提示词管理）以及全屏设置页，全部改为通过 `registry` 注册；5 个核心内置组件全部用 `<Overridable>` 包裹，消灭硬编码 `import` 墙。

### 2. 共享 React 运行时：用 `window.__POINTSTUDIO_RUNTIME__` 替代裸 `rollupOptions.external`

- **纠正误区**：在 Vite 生产构建（ESM）中直接配置 `rollupOptions.external: ['react', 'react-dom']` 且无 Import Map 时，浏览器会直接抛 `Failed to resolve module specifier "react"` 导致应用白屏。
- **正式方案**：宿主正常打包 React，并在启动入口由 `src/renderer/src/runtime/expose.ts` 挂载全局单例句柄：
  ```ts
  window.__POINTSTUDIO_RUNTIME__ = {
    React,
    ReactDOM,
    jsxRuntime,
    registry,
    store: studioStore
  }
  ```
  插件产物从 `__POINTSTUDIO_RUNTIME__` 取用同一个 React 实例，既保证 Hooks 单例不崩，又避免宿主构建白屏。

### 3. 外置响应式状态层（`studioStore`）与 60fps 性能铁律

把 `ChatPanel.tsx`（现 823 行）里的业务状态外置到 `src/renderer/src/store/studioStore.ts`（基于 React 原生 `useSyncExternalStore`，**不引入 Redux/Zustand**，严守零新增运行时依赖约束），并强制落地 **5 条性能铁律**：

1. **流式 chunk 16ms 帧对齐合并（RAF Batching）+ 动静切片分离**：
   - 主进程推来的 `chat:chunk` 先入内存缓冲池，每个 `requestAnimationFrame`（~16ms）最多合并刷新 1 次；
   - **将「正在流式生长的消息（`inflightMessage`）」与「已完成的历史消息数组（`historyMessages`）」在 Store 切片上彻底拆开**。流式吐字时，100 条历史消息组件 **0 重绘**。
2. **细粒度 Selector 订阅**：输入框只订阅 `busy / activeModel / effort`，侧栏只订阅 `conversations` 摘要，打字时消息流与侧栏纹丝不动。
3. **乐观 UI + 主进程 Write-Behind 尾部合并落盘**：前端操作 0ms 乐观更新；主进程 `JsonFileStore` 升级为内存热缓存 + 200ms 防抖合并落盘（`before-quit` 强制 flush）。
4. **长列表原生视口裁剪**：`.msg` 历史气泡启用 Chromium 原生 `content-visibility: auto; contain-intrinsic-size: 0 88px;`，零第三方虚拟列表开销。
5. **GPU 合成层动效纪律**：严禁对高频变化元素过渡 `width/height/top/left`，统一走 `transform` 与 `opacity`。

### 4. 故障自愈与崩溃回滚机制（不阉割权限，绝不陪葬）

| 机制 | 实现落点 | 行为契约 |
| --- | --- | --- |
| **1. Disposer 强制托管** | `runtime/registry.ts` | 插件通过 `PluginContext` 注册的一切页面、插槽、覆盖、样式、事件监听，其返回的 `Disposer` 自动归集到 `pluginDisposers.get(pluginId)`。禁用插件时宿主一键遍历执行，瞬间清空，不依赖插件作者自觉。 |
| **2. 渲染边界自动回退** | `runtime/guard.tsx` (`PluginErrorBoundary`) | 每个 `<Slot>`、`<Overridable>`、`<Page>` 均包裹带 `pluginId` 的错误边界。若覆盖组件（如自定义气泡）渲染抛错，**当场自动回退为内置 `Builtin` 组件**并记录故障计数；同一插件 5 分钟内连续抛错 3 次自动移入 `quarantined`（隔离停用）并发出 Warn 横幅。 |
| **3. 启动死锁看门狗** | `src/main/core/bootWatchdog.ts` (P1) | 主进程加载插件前写入 `userData/boot.lock`，渲染层首帧挂载完成后清锁。若插件死循环导致崩溃或强退，下次启动检测到残余 `boot.lock`，**自动进 Safe Mode（跳过所有第三方插件）**并在顶栏提示排障。 |
| **4. 目录级版本回滚** | `userData/plugins/.rollback/<id>/` (P1) | 升级或覆盖安装插件前自动备份上一可用版本，设置页支持一键回滚。 |

## 三、PointStudio 四大独家交互特色与协议底座

### 特色 1：驻场工位（Agent Bench）+ 顶栏派遣胶囊（Dispatch Pill）

- **单一 Session 双轴归属**：`Conversation`（即一次派遣 Session）持有 `assistantId`（Agent）与可选 `workspaceId`（项目）、`taskId`（任务卡）。
- **侧栏双轴联动**：在四段式侧栏中，点击某个 Agent 过滤出「该 Agent 跨项目的所有执行记录」；点击某个 Project 过滤出「该项目下不同 Agent 的执行记录」；未挂项目的随手聊归入固定入口「主聊天 / 临时会话」。
- **顶栏派遣胶囊**：主舞台顶栏提供组合胶囊 `[ 👤 Agent ⇄ 📁 Project · ⚡ 思考预算 ]`，支持在同一个会话现场**中途换 Agent 接力**（例如开发 Agent 写完，点一下切测试 Agent 进同一上下文审视）。

### 特色 2：记忆闪光（Memory Spark）

- 当对话产生明确纠正或阶段结论时，消息旁可触发 `[ ✦ 提炼为私域记忆 · 全局 / 仅本项目 ]`，写入该 Agent 的作用域记忆库（参见 ADR 0006）；输入时轻度提示本轮已唤醒的私域记忆条目。

### 特色 3：双轨时间线（Dual-Track Stream）+ 原地透镜

- Agent 多步执行或工具调用默认在消息气泡上方收敛为单行脉冲轨：`[ 🧭 4 步已完成 · 耗时 1.8s ▾ ]`；点击后在气泡内**原地展开步骤透镜卡**（工具名、输入输出摘要 `summary`、耗时、错误码），不再依赖遮挡右侧的抽屉。

### 特色 4：PandaOrchestrator 本地协同路由与自动升档梯队（预留标准协议槽）

对标并支持无缝集成 [AICodeKing/PandaOrchestrator](https://github.com/aicodeking/PandaOrchestrator)（31MB 本地 ONNX 任务画像模型 + 模型卡匹配 + 失败升档阶梯 `escalation_ladder`）：

- **内核协议槽（`RouteDecisionDto`）**：在 `src/shared/types/ipc.ts` 预留纯 JSON 路由决策结构，并在 `MessageDto` 与 `AgentStepDetailDto` 上增加可选字段 `route?: RouteDecisionDto`：
  ```ts
  export interface EscalationStepDto {
    model: string
    providerId?: ProviderIdDto
    pSuccess: number
    estCostUsd?: number
  }

  export interface RouteDecisionDto {
    traceId: string
    chosenModel: string
    providerId?: ProviderIdDto
    decidedBy: string                  // 如 "policy:cheapest_above_threshold" | "static:session"
    confidence: number                 // 预估成功率 0~1
    difficulty: {
      level: number                    // 1~10 难度级
      category: string                 // 如 "implementation" | "debugging" | "architecture"
    }
    estCostUsd?: number
    estLatencyMs?: number
    attempt?: number                   // 当前处于升档阶梯第几棒（默认 1）
    escalatedFrom?: string             // 若发生了失败自动升档，记录上一棒失败的模型名
    escalationLadder?: EscalationStepDto[]
  }
  ```
- **工作流闭环**：
  1. 未安装路由插件时，走内置 `StaticRouter`（按 `会话级模型 > 助手模型 > 全局默认` 产出基础决策）；
  2. 安装 `panda-router` 插件（连接本地 Panda HTTP/MCP 或本地 ONNX）后，输入栏模型下拉激活 **`[ 🐼 Auto · 协同路由 ]`**；
  3. 发送时 10ms 内由路由器剖析任务难度与类别，优先派高性价比小模型；若步骤失败或用户点「升档重试」，自动顺着 `escalationLadder` 切换下一棒强模型；
  4. 执行结束后的 L1 行为信号（成败、是否被重发、实际耗时）通过 `RouterPort.reportOutcome(traceId, outcome)` 回流校准本地模型能力卡。

## 四、面向 Rust 版本（新仓库）的跨语言边界铁律

1. **`src/shared/types/ipc.ts` 只许放纯 JSON 数据结构（DTO）与常量**：严禁出现 Class 实例、函数回调、`Map/Set` 或 Electron 专有类型。将来在 Rust 仓库中该文件 1:1 映射为 `serde` 的 `#[derive(Serialize, Deserialize)]` struct。
2. **渲染层零 Node/Electron 直连**：`src/renderer` 与所有 UI 插件只认 `window.pointstudio`（Preload 桥）与 `PluginContext`。将来底层从 Electron IPC 换成 Tauri Command 或 Rust WebSocket 时，`src/renderer` 与全部 UI 插件 **0 行代码修改即可运行**。
3. **本地决策模型跨语言复用**：PandaOrchestrator 的核心是 31MB `.onnx` + `cards/*.json`，在 Rust 版中直接由 `ort` (ONNX Runtime Rust crate) 原生加载，彻底摆脱 Python 运行时依赖。
