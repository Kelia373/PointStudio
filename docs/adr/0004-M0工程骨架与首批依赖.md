# ADR 0004 · M0 工程骨架与首批依赖

- 状态：**已接受**
- 日期：2026-11-21
- 决策人：Alpha（依赖清单已在会话中逐项放行）
- 关联：`ADR 0002`（技术栈选型）。本文只解决"第一批代码怎么落地"，不改变 0002 的选型结论。

## 背景

M0 的目标是打通"窗口能开、文字能动"的最短链路，用来前置 Electron 工具链风险，同时让仓库从"只有文档"变成"能跑的东西"。在此之前仓库没有根 `package.json`，`apps/desktop` 只有一份 README。

## 决策

| # | 决策 | 选择 | 理由 |
| --- | --- | --- | --- |
| 1 | 包管理 / 布局 | pnpm workspace，`apps/*` + `packages/*` | 与 ADR 0002 一致；`packages/*` 还没有 `package.json` 时 workspace 会自然跳过 |
| 2 | 桌面构建链 | `electron-vite` | main / preload / renderer 三段由一份配置管；比手拼 vite + 自写 dev 脚本少一半胶水 |
| 3 | 版本 | electron 45 / electron-vite 6 / vite 8 / react 19 / typescript 7 | 由 pnpm 解析最新稳定版后锁定，不手工猜版本 |
| 4 | 机器状态位置 | 依赖缓存与 electron 二进制**外置到 `D:\deveTools`**：pnpm 内容仓库由 `pnpm-workspace.yaml` 的 `storeDir` 指定，electron 下载缓存用 `ELECTRON_CACHE` | 仓库只放源码；`node_modules` 是 Node 模块解析硬要求，无法外置，但已被 `.gitignore` 忽略 |
| 5 | 依赖构建脚本放行 | `pnpm-workspace.yaml` 的 `onlyBuiltDependencies: [electron, esbuild]` | pnpm 10+ 默认不跑 postinstall；不放行则 electron 装完没有二进制 |
| 6 | 类型配置 | 单一 `apps/desktop/tsconfig.json` | 现阶段没有跨包类型边界，拆 node/web 两份只增加维护面；构建由 esbuild 负责，tsconfig 只服务 IDE 与 `tsc --noEmit` |
| 7 | M0 明确不做 | 打包安装包、Tailwind、shadcn/ui、路由、SQLite | 每引入一样就多一个待排的坑，M0 只验证链路 |

## 后果

**正面**：`pnpm install` → `electron-vite build` → 三份产物全部生成；类型检查零错误；依赖版本有 lockfile 锁定。

**负面 / 风险**：

- **工作区目录会阻止程序执行（本机最大的坑，已实测）**：DSH 给 session workspace 目录加了 ACL 加固，工作区内的 exe 在用户普通进程里静默失败（无输出、退出码 0、不执行、事件日志为空）。同一个 electron.exe 在 `D:\etest`、`D:\Project\etest2`（工作区外）正常，在 `D:\Project\PointStudio` 内连 `--version` 都无输出；`NewGame` / `PointStudio` / `PointStudio-Enterprise` 三个工作区都带同样加固。**因此"换个目录重建 workspace"无效**。
  **采用的解法**：依赖实体装在工作区外 `D:\deveTools\ps-node`，再用目录 junction 把 `node_modules` 与 `apps/desktop/node_modules` 链进工作区；源码仍留在工作区。代价是改依赖后要多一步同步 `package.json` 到 `ps-node` 再 install。
- **electron postinstall 在本机被 pnpm 跳过**，二进制要手动 `node install.js` 补齐，且需 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`（本机直连 GitHub HTTPS 被阻断）。换机器时要重做一次。
- **GUI 无法在 AI 会话里验证**：electron 进程在本执行环境以 `0xC0000005` 崩溃（提权后同样），属环境限制。窗口是否正常只能由人开终端确认，CI 也不覆盖。
- **typescript 7 移除了 `baseUrl`**，`paths` 必须用相对路径（`./src/...`）。这条在引入 TS 6 及以下的机器上不成立，届时改回即可。
- 首次 `pnpm install` 若 `storeDir` 未生效，store 会落到仓库内的 `.pnpm-store/`（已加 `.gitignore` 兜底，但仍是本机配置问题的信号）。设置项写在 `pnpm-workspace.yaml`，写到 `.npmrc` 的 `store-dir` 在 pnpm 11 下不生效。
