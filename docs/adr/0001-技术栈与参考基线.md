# ADR 0001 · 技术栈与参考基线

- 日期：2026-11-20

## 背景

仓库刚初始化，尚无代码。需要先定：运行形态、技术栈、包管理、参考基线。

## 现状事实

  当前为浅克隆的未检出状态，读源码前需先 `sparse-checkout` 或完整 checkout。
- 本机无 `gh` CLI、无 SSH key；git 推送需提权出网。

## 待决策项

1. **参考基线**：`cherry-studio` 用于参考什么？——架构分层、插件/工具体系、模型接入方式、桌面端形态。**只读，不抄代码**。
2. **运行形态**：桌面端（Electron / Tauri）、Web、还是两者共存。影响面：安装包体积、系统集成能力、企业版私有化难度。
3. **语言与工具链**：TypeScript 全栈为主 / 后端引入其它语言。影响面：企业版部署、性能敏感模块。
4. **仓库结构**：`apps/` + `packages/` 单仓，是否引入 monorepo 工具（pnpm workspace 等）。
5. **工具/插件协议**：自研协议 vs MCP。影响面：生态兼容性、企业版白名单管控。
6. **数据存储**：本地 SQLite / 文件 / 服务端数据库；企业版是否需要独立存储层。

## 提议方向（待确认，未生效）

- 单仓多包：`apps/desktop`、`apps/server`、`packages/agent-core`、`packages/tools`、`packages/policy`。
- 内核与外壳解耦：`packages/` 不含任何 UI 依赖，保证个人版/企业版共用。
- 个人版与企业版差异集中在 `packages/policy`，内核不分叉。

## 后果

若采用上述方向：内核可测试性好、两版不分裂；代价是前期要在抽象层多花时间，短期看不到界面产出。
